# 验证记录 · 0.2.0

日期：2026-10-13。对象：以独立 Brief / Prompt 为主交付的本地修订版。

本记录区分静态检查、安装分发、生成行为与下游执行。手写示例不是实测；旧版的“确认后执行”试跑不作为本版流程的验证证据。

## 实际设置

- 环境为 Windows PowerShell，Python 3.12.10，Skills CLI 1.7.2。
- A、B、C 及前提检查变体由独立子 Agent 显式读取 Skill 和按需引用后生成，未继承项目对话，也未读取 README、手写示例、验收标准或其他试跑输出。模型沿用当前会话配置；没有进行跨模型比较。
- 修改与认可测试延续各自生成对话，检查多轮行为。保存响应的本地文件操作属于测试记录，不代表用户要求了额外研究文档。
- 本轮测试只要求生成或修订任务，不要求执行其中的调查。各执行者报告仅使用本地读取、写入及文件核验工具，未调用联网研究工具。
- 发现预算语义混淆后补充规则，并以相同输入另开独立上下文复测 C。最终还收紧了“现有架构”表述：仅用户要求保留的部分属于约束；未单独实测后端案例。
- 原始响应保存在被 Git 忽略的本地验证目录；本文件仅记录输入范围、观察和限制，不发布原始对话或调试日志。

## 三类核心案例

输入与验收条件见 [cases.md](cases.md)。

| 案例 | 实际观察 | 结论 |
| --- | --- | --- |
| A 优秀个人作品搜索 | 直接给完整 Prompt；包含平台与用途覆盖、来源、个人开发身份核实、去重及简短清单。近期范围和约 20 项均标为可调整默认，不要求深度评测或固定并发 | 本次生成达到该场景条件；没有先提问或执行搜索 |
| B 推广方法调查 | 分别处理独立游戏与开源 App，写到具体入口、发布规则、素材与示例、跟进动作、投入和判断信号；来源与建议分开，控制为少量优先路线 | 本次生成达到该场景条件；没有扩展成营销团队或实际发布 |
| C 游戏引擎深度研究 | 首轮把“预算充足”延伸成可以考虑付费工具和服务。修订后独立复测保留预算含义的不确定性，按场景比较成本；同时给出团队与 AI 使用核验、失败案例、独立探索、小型试验和停止条件，不固定并发或唯一赢家 | 首轮偏差已针对性修正；复测达到该场景条件，没有开展下游研究 |

这些观察支持按目的区分搜索、实用调查和深入研究的生成能力；不是整体质量评分，也不说明研究结论已经验证。
