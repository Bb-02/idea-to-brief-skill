# 想法成案 · Idea to Brief

**把零散想法，整理成可以独立交给 AI 执行的研究任务或提示词。**

Turn rough ideas into self-contained, actionable research briefs and prompts.

你不必先学会领域术语或自己设计研究流程。这个 Skill 帮你理解目的、检查关键前提、补上有价值的角度，再写出目标明确、范围适当、方法具体的任务说明。你可以交给当前 AI，也可以复制给其他 AI。

**主要交付就是这份任务说明。** 信息足够时直接给草案，根据反馈修订；只有你明确要求继续执行，当前 Agent 才开展后续任务。

## 从“想研究一下”，到可以交出去的任务

**你说：**

> 我一个人做游戏，也做开源小工具，但不知道怎么让别人发现。没粉丝、没团队，大家都说做内容、运营社区，可我还是不知道具体干什么。帮我写个调查任务，要能照着做，别搞得太复杂。

**AI 直接给出可用的任务草案：**

> 请调查个人独立游戏与开源应用的冷启动推广方法，分别给出适合没有现成受众、由一个人执行的行动建议。
>
> 优先寻找开发者本人复盘、平台官方规则和可核实的项目案例。研究最早的用户从哪里来，也看普通项目和失败经验，区分案例实际做法与对我的建议。
>
> 对值得尝试的渠道，说明适合什么产品、在哪里接触目标用户、准备什么素材、怎样发布或参与、给一个内容示例，以及发布后怎样跟进。标明大致投入和什么信号值得继续或停止。涉及平台规则与费用时核实当前资料，不编造效果数字。
>
> 分别给出游戏和开源应用能开始执行的安排，并用简短对照说明优先渠道、适用条件和主要限制。避免让一个人同时经营所有平台；做到能决定先在哪里、用什么材料采取行动即可。

**你修改：**

> 这次只看开源应用，先不研究游戏。不想花钱投广告，简短一点。

**AI 交付完整新版：**

> 请调查个人开源应用如何获得最早一批用户，限定一个人能执行、无需付费广告的方法。优先查开发者复盘、相关社区和平台官方规则，寻找实际触达用户的渠道及可核实案例。
>
> 对优先方法写清适合什么应用、去哪找用户、准备什么素材、如何发布或参与，给出内容示例、后续动作和继续或停止的信号。交付简短的渠道对照与起步安排，附来源；经验与建议分开，无法确认的效果数字保持未知。

这里的价值是：**识别目的 → 补全研究问题与方法 → 控制范围 → 交付可独立使用的任务 → 根据反馈修订。**

以上是手写示范，不是实际研究结果。三类完整示例见 [examples.md](examples.md)：优秀个人作品搜索、推广方法调查、游戏引擎深度研究。

## 什么时候用

- 想找作品、工具或灵感，但还没组织好覆盖范围和筛选要求。
- 想调查某种做法，希望把泛泛的话变成具体比较、操作步骤和交付要求。
- 想深入研究复杂问题，需要把问题拆开、选择证据与方法，并控制投入。
- 开发前有不成熟的技术想法，需要把猜测转成可验证的调查任务。

已经清楚的事实问题、直接执行请求和常规开发任务沿用原流程。这个 Skill 重点服务于整理任务、编写或修改研究任务说明与提示词。

自动选择主要看你需要什么交付：想直接得到解释或调查结果，沿用普通流程；有调查方向，但需要理清该查什么、怎样比较和最后交付什么，适合使用本技能，无需先说出“提示词”。仅表示“以后可能用得上”仍可能是普通交流，不要求必定触发。实际选择还受客户端和模型影响，边界对照见 [行为验收场景](tests/cases.md)。

## 怎样展开，怎样收住

| 任务 | 重点 |
| --- | --- |
| 简单搜索 | 覆盖不同方向、基本核实、筛选、去重、来源和简短整理 |
| 实用调查 | 可比较的依据、适用条件、具体动作与内容示例 |
| 深入研究 | 按需安排独立探索、反例、关键验证、阶段汇总和资源分配 |

广度、深度、输出长度、预算与并发分别判断。很多 Token 不代表要写很多文档，题目广也不代表每个候选都要深挖。研究资源与项目开支也分别处理；模糊的“预算充足”不会被写成已接受付费工具或服务。

AI 会区分目标、硬约束、偏好、举例和自己的补充。可能错误的前提应成为待验证的问题；没有依据时不会把猜测写成事实。你说“那个只是举例”“取消旧限制”“这次简单一点”，它会更新整份任务说明。

“想弄明白，以后也许用得上”会先整理成适度的探索任务，不自动升级成正式项目、长报告或完整设计方案。个人观察可以成为研究起点，不需要先证明用户想错了；模型补充的解释也要有证据，未确定的预算、经历与资源不会被写成用户事实。

信息足够就给可用草案。只有缺失信息会实质改变任务时才询问，确认不会成为每次生成任务说明的固定关卡。

## 安装

当前 `0.2.1` 是本地修订版；下面使用本地目录安装。后续发布另行决定。

在本仓库目录运行 [Skills CLI](https://github.com/vercel-labs/skills)：

```bash
npx skills add . --skill idea-to-brief
```

例如，指定 Codex 并复制文件：

```bash
npx skills add . --skill idea-to-brief --agent codex --copy
```

默认是项目安装；需要全局安装时添加 `--global`。也可以复制整个 `skills/idea-to-brief/` 到客户端指定的 Skill 目录，保留参考文件、元数据和许可证。位置以客户端当前文档为准。

CLI 能分发到某个客户端，不代表本项目已验证该客户端的自动触发或实际研究能力。

## 使用

支持显式 Skill 调用的环境中，例如：

```text
$idea-to-brief 我想找一些优秀的个人开发作品，移动端和桌面端都看看。重在开眼界，别做很深，帮我整理成搜索任务。
```

也可以继续修改：

```text
这个例子只是说明我喜欢的感觉，别把方向限制死。
只看 Windows，保留来源和基本筛选，其他部分缩短。
把旧的两个并发限制取消，按执行环境来。
给我完整新版提示词，方便直接交给另一个 AI。
```

输出默认是可以复制的普通 Markdown。中文交流时按用途称为“任务说明”“研究任务”或“提示词”，无需反复插入英文标签；你指定的术语与必要技术名称会保留。简短任务无需单独文件或统一长模板。指定目标模型时保留你的要求，但不会假设它拥有未提供的工具。

如果希望当前 Agent 继续执行，可以明确说“按这份任务开始研究”。对草案说“不错”或要求修改，默认仍停留在任务说明交付。

## 能力与边界

Skill 的写作行为与任务说明中的执行行为分别处理。为写出可靠任务，必要时先读已有资料或有限查证关键前提；大量搜索、研究子 Agent 和文档生产应按需写入后续任务，不在写提示词时默认展开。

需要当前事实的任务，会要求执行者实际核实来源与相关日期。无法访问资料或工具时，说明限制，保留未知，不编造查证或执行结果。

多 Agent、红队和固定阶段都按需选择。并发遵守宿主和用户当前限制，包含嵌套任务；未指定时不虚构固定数字。临时失败有限重试，持续失败说明缺口并寻找可行替代。文字要求不等于运行时调度保证。
