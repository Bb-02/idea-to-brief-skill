# 想法成案 · Idea to Brief

**简体中文** | [English](README.en.md) · [v1.0.0](https://github.com/Bb-02/idea-to-brief-skill/tree/v1.0.0)

**把模糊想法，变成有章法的调查。**

一个帮助 AI 组织搜索、调查和研究的 Skill：找准你真正想解决的问题，检查未经验证的假设，补上必要角度，选择合适的资料与方法。

- **想先理清任务：** 生成完整、可交给当前或其他 AI 的研究任务 / 提示词，默认到此结束。
- **想直接得到答案：** 实际调查并交付有来源的结论与建议。

[应用场景](#适合做什么) · [实测效果](#实测一句话启动并行调查) · [安装](#安装) · [使用](#使用)

## 适合做什么

| 场景 | 例如 | 研究重点 |
| --- | --- | --- |
| 搜索资料与灵感 | 找优秀个人作品、工具、参考案例 | 覆盖不同方向，筛选、去重与基础核实 |
| 调查实际问题 | 活动爽约、作品推广、方案比较 | 查具体证据、替代办法与实施成本 |
| 深入研究复杂问题 | 比较游戏引擎、探索技术路线 | 拆解关键问题，验证重要主张、寻找反例 |

简单搜索保持轻量，复杂问题按需深入；普通事实问答不必展开研究。

## 实测：一句话启动并行调查

用户在装有本 Skill 的 ZCode 中用 Qwen 测试，**只说了：**

> 我们读书会经常有人报名却不来，我觉得免费活动就是没人珍惜，收点钱应该就好了。帮我调查一下别人遇到这种情况怎么处理，给我一些有依据、能尝试的办法。

据用户实测反馈，**AI 自动生成任务提示词，分发给三个子 Agent 并发调研**。以下完整展示用户提供的其中两条原文，均由 AI 生成。

<details open>
<summary><strong>子 Agent 1：研究证据、收费效果与替代机制（完整原文）</strong></summary>

> 你是一名调研员，请用 WebSearch 和 WebFetch 做一手资料检索（不要凭记忆编造，所有结论必须附来源 URL 和大致年份）。
>
> 背景：一个志愿者运营的免费读书会经常遇到报名者爽约（no-show），组织者猜测"收费就能解决"。需要检验并扩展这个假设。
>
> 请调研以下问题，重点是**有研究或数据支撑**的结论：
>
> 1. 免费活动 vs 收费活动的爽约率差异：有没有行业统计数据（如 Eventbrite、Meetup、活动管理平台发布的 no-show 数据）？大概数字是多少？
> 2. 行为经济学/心理学解释：沉没成本、付款之痛（pain of paying）、承诺机制（commitment device）——收费减少爽约的机制是什么？有没有经典实验？例如 Volpp 等人在 NEJM 等期刊发表的"押金/小额金钱激励减少预约爽约"实验（milk-deposit study），请核实其设计、数字和结论。
> 3. 收费的副作用：收费是否会吓退报名、改变人群构成？有没有证据？
> 4. 不收费但同样有效的机制：预约确认提醒（尤其是 SMS/短信提醒在医疗预约领域的效果研究，量化降低爽约率的数据）、可退还押金（deposit 到场即退）、公开承诺、候补名单（waitlist）、社会规范/同伴压力、签到制、习惯性缺席惩罚（如三次取消规则）——每一项找有没有实证或可靠实践来源。
> 5. 有没有"押金可退"优于"直接收费"的证据？
>
> 要求：
>
> - 用中英双语关键词搜索（如 "no-show rate free vs paid events", "commitment device reduce no-show", "appointment reminder SMS reduce no-show percentage", "金钱激励 爽约 预约"）。
> - 每条结论标注：来源标题、URL、年份、是同行评议研究/行业报告/从业者经验（分层）。
> - 明确区分"证据支持""证据相互矛盾""只是说法"。
> - 找不到的就直说找不到，不要编造数字。
>
> 输出：中文调研报告，结构化列出发现，每条附来源。

</details>

<details>
<summary><strong>子 Agent 2：社群实践、平台机制与反面经验（完整原文）</strong></summary>

> 你是一名调研员，请用 WebSearch 和 WebFetch 检索**真实社群组织者的实践经验**（不要凭记忆编造，结论附来源 URL）。
>
> 背景：一个免费读书会（几十人规模，志愿者运营，线下或线上线下混合）报名者经常爽约。我们想知道其他俱乐部/社群/Meetup 组织者实际用什么办法治理"报名不来"，以及效果如何。
>
> 请调研：
>
> 1. Reddit（r/Meetup、r/community、r/nonprofit 等）、Meetup 社区论坛、活动运营博客里，组织者讨论"no-show / people don't show up"的帖子：他们总结了哪些有效做法？哪些被证明无效？特别注意一手经验帖（"我们试过 X，结果是……"）。
> 2. Meetup / Eventbrite / Luma / 活动行 / 互动吧 等平台自带的机制：RSVP 管理、押金（deposit）、候补名单、自动提醒、no-show 标记/取消资格功能——各自怎么用、平台文档怎么说。
> 3. 具体做法清单及其在实践中的反馈：
>    - 收取象征性费用（哪怕 1-5 元）或到场退还的押金
>    - 活动前 24 小时要求"确认参加"，不确认视为取消、释放名额给候补
>    - 三次爽约拉黑/限制报名规则
>    - 报名截止 + 名额限制 + 候补名单
>    - 微信群接龙/报名接龙、签到表、拍照留档
>    - 小组化（固定班底、互相认识）来提高出席动力
>    - 收费模式的社群（如付费读书会）实际出席率如何，免费转付费的组织者怎么说
> 4. 有没有反面经验：收费/押金导致报名骤降、气氛变差、志愿者难执行的案例？
>
> 搜索建议：用英文如 "meetup organizer how to reduce no-shows reddit", "eventbrite deposit no show", "how to stop people from flaking on your meetup", 中文如 "读书会 报名 爽约 押金", "活动 鸽子 怎么办 社群"。
>
> 要求：每条做法注明出处和来源类型（平台官方文档 / 从业者一手帖 / 运营文章），有数字的抄数字，找不到量化数据的就说明只是经验谈。不要编造。
>
> 输出：中文结构化报告：有效做法清单（按证据强度排序）、无效或有风险的做法、来源列表。

</details>

任务从“收费能否解决”扩展到**收费副作用、替代办法和真实实践**，并明确了资料来源、检索词与证据要求。

<sub>以上为用户提供的任务分发记录，非最终研究报告；补充背景与具体研究线索仍需核实。并发数量由任务与客户端决定。</sub>

## 安装

使用 [Skills CLI](https://github.com/vercel-labs/skills)：

```bash
npx skills add Bb-02/idea-to-brief-skill --skill idea-to-brief
```

指定 Codex 并复制安装可添加 `--agent codex --copy`；全局安装添加 `--global`。

**手动安装：** [下载源码 ZIP](https://github.com/Bb-02/idea-to-brief-skill/archive/refs/tags/v1.0.0.zip)，把整个 `skills/idea-to-brief/` 文件夹复制到客户端的 Skill 目录。

## 使用

支持 `$技能名` 调用的客户端可以这样使用：

**先整理成任务：**

```text
$idea-to-brief 我想了解个人开发者怎么推广作品。
帮我整理成可交给另一个 AI 的调查任务。
```

**直接调查：**

```text
$idea-to-brief 调查个人开发者怎么推广作品，
给我有案例依据的渠道比较和起步建议。
```

其他客户端可通过技能入口选择 `idea-to-brief`。自动调用效果取决于模型与客户端；联网和子 Agent 能力由客户端提供，多 Agent 并非必需。
